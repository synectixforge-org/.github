## Open-Source Contribution Workflow

Synectix Forge is an open-source community where contributors can either join existing projects or propose new ideas and build them together with people from around the world.

<pre>
<a href="https://github.com/synectixforge-org">Synectix Forge</a>
│
│
├── 1. Choose How You Want to Contribute
│   │
│   ├── Existing Project
│   │       │
│   │       └── Explore <a href="https://github.com/synectixforge-org">GitHub Projects</a>
│   │
│   └── New Project / Idea
│           │
│           └── Go to <a href="https://discord.com/channels/1418661630903976009/1523268168506937444">#project-ideas</a>
│
│

│   │
│   ├── Choose a Project
│   │   │

│   ├── Look for

│   │
│   ├── <a href="https://github.com/synectixforge-org/EngineLab/issues">EngineLab Issues</a>

│
├── 2B. NEW PROJECT / IDEA
│   │

│   ├── Create a new post
│   │
│   ├── Describe
│   │   ├── What you want to build

│   │
│   └── Find people interested in building it

├── 3. Find Your Team
│   │

│
├── 4. Find an Active Project
│   │
│   └── <a href="https://discord.com/channels/1418661630903976009/1523269754616549457">#active-projects</a>
│       │
│       ├── Explore ongoing projects
│       ├── Find projects looking for contributors
│       └── Join a project team
│
│
├── 5. Start Contributing on GitHub
│   │
│   ├── Fork the Repository
│   │   │
│   │   ├── Official
│   │   │   └── synectixforge-org/PROJECT
│   │   │
│   │   └── Your fork
│   │       └── YOUR-USERNAME/PROJECT
│   │
│   ├── Clone Your Fork
│   │   │
│   │   └── git clone
│   │       └── https://github.com/YOUR-USERNAME/PROJECT.git
│   │
│   ├── Connect Official Repository
│   │   │
│   │   ├── origin
│   │   │   └── YOUR-USERNAME/PROJECT
│   │   │
│   │   └── upstream
│   │       └── synectixforge-org/PROJECT
│   │
│   └── Create a Branch
│       │
│       ├── feature/add-new-feature
│       ├── fix/bug-description
│       └── docs/update-documentation
│
│
├── 6. Develop
│   │
│   ├── Write code
│   ├── Follow project conventions
│   ├── Keep changes focused
│   └── Do not include secrets
│
│
├── 7. Test
│   │
│   ├── Run automated tests
│   ├── Build the project
│   └── Manually verify functionality
│
│
├── 8. Commit
│   │
│   ├── git add .
│   │
│   └── git commit
│       ├── "Fix collision detection"
│       ├── "Add keyboard controls"
│       └── "Improve documentation"
│
│
├── 9. Push to Your Fork
│   │
│   └── git push
│       └── YOUR-USERNAME/PROJECT
│
│
├── 10. Open Pull Request
│   │
│   ├── From
│   │   └── YOUR-USERNAME/PROJECT
│   │
│   └── To
│       └── synectixforge-org/PROJECT → main
│
│
├── 11. Code Review
│   │
│   ├── Maintainer reviews PR
│   │
│   ├── Changes requested
│   │   └── Update the same branch
│   │
│   ├── Questions / discussion
│   │
│   └── Approval
│
│
├── 12. Merge
│   │
│   └── Pull Request
│       └── main
│           └── Synectix Forge
│
│
└── 13. Continue Contributing
    │
    ├── Sync your fork
    │   └── git fetch upstream
    │
    ├── Find another issue
    │
    ├── Join another project
    │
    └── Create a new branch
        └── Repeat the workflow
</pre>

## Project Discovery

Use GitHub **Topics** to categorize repositories:

<pre>
Games        → games, game-engine, simulation
Physics      → physics, simulation, numerical-methods
Electronics  → electronics, circuits, embedded
Tools        → developer-tools, utilities
Audio        → audio, signal-processing, music
AI           → artificial-intelligence, machine-learning
Web          → javascript, web, frontend
Fun          → experiments, creative-coding
</pre>

Topics describe **what a repository is**.

Labels describe **what is happening inside a repository**.

Git tags should primarily be used for **versions and releases**:

<pre>
v0.1.0
v0.2.0
v1.0.0
v1.1.0
</pre>
